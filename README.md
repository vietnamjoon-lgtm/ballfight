# BOUNCE · 나만의 원형 배틀

정사각형 경기장에서 원형 캐릭터 두 명이 벽에 튕기며 자동으로 싸웁니다. 캐릭터마다 체력, 이동 속도, 크기, 접촉 피해와 최대 3개의 능력을 정할 수 있습니다.

## 실행

압축 파일을 풀고 `index.html`을 브라우저로 여세요. 같은 폴더의 나머지 파일도 필요합니다. 설치, 빌드, 로그인, 서버가 필요 없습니다.

캐릭터 두 명을 선택하고 **대전 시작**을 누릅니다. 같은 캐릭터끼리도 싸울 수 있습니다. 일시정지와 속도 조절을 지원합니다. 캐릭터 선택을 바꾸거나 설정을 저장하면 현재 경기는 준비 상태로 돌아갑니다.

## 코드 없이 캐릭터와 능력 추가

1. 위쪽 **캐릭터 · 능력 만들기 ＋**를 누릅니다. 전투 중이면 일시정지됩니다.
2. **새 능력**을 누르고 이름, 동작 종류, 쿨타임, 피해량 등을 입력한 뒤 **능력 저장**을 누릅니다.
3. **새 캐릭터**를 누르고 이름, 색상, 체력, 이동 속도, 크기, 접촉 피해를 정합니다. PNG·JPG·WebP 사진도 넣을 수 있습니다.
4. 보관함에서 능력을 최대 3개 선택한 뒤 **캐릭터 저장**을 누릅니다.
5. 경기장의 캐릭터 선택 목록에 새 캐릭터가 나타납니다. 새 캐릭터는 첫 번째 선수로 자동 선택됩니다.

기존 항목은 편집할 캐릭터/능력 목록에서 골라 수정합니다. 능력을 수정하면 그 능력을 장착한 모든 캐릭터에게 적용됩니다. 편집 창에서 입력만 한 내용은 아직 저장되지 않은 초안입니다.

## 저장과 공유

- 저장 버튼을 누르면 현재 브라우저의 저장 공간에 보관합니다. 시크릿 모드, 브라우저 설정, 저장 공간 부족 등으로 저장하지 못하면 화면에 알립니다. 이 경우 현재 창에서는 사용할 수 있으나 새로고침하면 사라질 수 있으므로 내보내기를 사용하세요.
- **설정 파일 내보내기**: `bounce-roster.json`을 다운로드합니다. 다른 브라우저에서 **설정 파일 불러오기**로 가져올 수 있습니다.
- 불러오기는 파일 검증과 개수 확인 후 **이 설정으로 교체**를 눌러야 적용됩니다. 현재 보관함을 대체하므로 필요한 설정을 먼저 내보내세요.
- **공유용 캐릭터 파일**: 현재 보관함을 담은 `characters.js`를 다운로드합니다. 게임 폴더의 기존 `characters.js`를 이 파일로 교체하면 다른 사람이 처음 게임을 열 때도 나만의 캐릭터가 기본으로 표시됩니다.
- 브라우저에 이미 저장된 보관함은 기본 파일보다 우선합니다. 기존 사용자에게 업데이트된 보관함을 적용하려면 새 JSON 설정 파일을 불러오세요.
- 캐릭터 사진은 160×160으로 줄여 설정에 함께 저장합니다. 별도 이미지 서버로 전송하지 않습니다.

## GitHub에 보관하기

이 폴더의 파일을 함께 저장하면 됩니다. `index.html`과 여덟 개의 JavaScript 파일, `styles.css`가 같은 위치에 있어야 합니다. 정적 파일만 사용하므로 GitHub Pages로 제공할 수 있습니다. 이 작업에서는 저장소 생성이나 업로드, 공개 배포는 수행하지 않았습니다.

## 능력 종류

| 종류 | 동작 | 바꿀 수 있는 값 |
|---|---|---|
| 탄환 발사 | 상대를 향한 부채꼴 발사 | 피해, 수, 속도, 간격, 벽 반사 횟수 |
| 돌진 | 발동 순간의 상대 방향으로 돌진 | 추가 피해, 속도, 지속 시간 |
| 충격파 | 발동 순간 범위 안의 상대 공격 | 피해, 범위 |
| 회복 | 자신을 회복 | 회복량 |
| 보호막 | 피해를 흡수 | 흡수량, 지속 시간 |
| 회전 무기 | 캐릭터 주변을 도는 무기 소환 | 피해, 수, 반경, 지속 시간, 회전 속도 |

각 능력은 자기 쿨타임만큼 기다린 뒤 처음 발동합니다. 탄환은 적중하거나 수명이 끝나면 사라집니다. 돌진의 추가 피해는 한 번의 돌진에 한 번만 적용됩니다. 보호막과 회전 무기는 다시 발동하면 이전 효과를 교체합니다. 회복은 최대 체력을 넘지 않습니다. 접촉 피해의 연속 적용 간격은 0.35초입니다.

## 궁극기

일반 스킬을 한 번 쓸 때마다 궁극기 게이지가 20%씩 찹니다. 5번 쓰면 가득 차고, 방금 쓴 스킬 동작이 끝나는 대로 궁극기가 자동으로 발동합니다. 게이지는 점수판과 캐릭터 둘레의 금색 원으로 표시됩니다. 궁극기가 도는 동안에는 일반 스킬 쿨타임이 멈춥니다.

- **늘어나는 코 → 코 분쇄기**: 코를 쭉 뻗은 채 2초 동안 분쇄기처럼 빙글빙글 돌며 휘두릅니다. 닿을 때마다 피해를 주고 밀쳐내며, 같은 상대는 0.25초 간격으로 다시 맞습니다. 도는 동안 벨트 그라인더 소리가 반복 재생되고, 끝나면 잦아듭니다. 편집기에서 **궁극기 타격 피해**와 **궁극기 코 길이**를 바꿀 수 있습니다.
- 궁극기는 1:1 대전에서만 동작합니다. 코드로 새 궁극기를 추가하려면 능력 종류에 `ultimate: { name, duration, cast }`를 넣습니다.

60초부터 보호막을 무시하는 장기전 피해가 점점 커집니다. 120초까지 끝나지 않으면 남은 체력 비율이 높은 쪽이 승리하며, 같으면 무승부입니다.

## 완전히 새로운 동작 추가하기

편집 화면은 등록된 동작의 수치와 조합을 만드는 곳입니다. 새로운 동작 자체(예: 소환수, 지형 생성)는 코드를 작성해야 합니다. `abilities.js`의 끝에 다음처럼 등록하면 **동작 종류** 목록과 입력란이 자동으로 늘어납니다. 아래 예시는 상대에게 즉시 피해를 주는 능력입니다.

```js
globalThis.ArenaAbilities.lightning = {
  label: '번개',
  description: '거리와 관계없이 상대에게 즉시 피해를 줍니다.',
  fields: {
    damage: { label: '피해', min: 1, max: 100, step: 1, default: 12 }
  },
  cast(api, self, target, params) {
    api.damage(target, params.damage, self);
    api.ring(target, 80, '#ffe38c');
  }
};
```

등록 후 게임을 다시 열고 새 능력을 만들 때 **번개**를 선택합니다. 새 동작을 쓴 설정을 다른 사람에게 공유할 때는 수정한 `abilities.js`도 함께 제공해야 합니다. 설정 파일 안에는 실행 코드를 넣지 않습니다.

`cast`에서 사용할 수 있는 도구:

| 함수 | 역할 |
|---|---|
| `api.damage(target, amount, self)` | 보호막을 반영한 피해 |
| `api.heal(self, amount)` | 최대 체력까지 회복 |
| `api.ring(self, range, color)` | 원형 이펙트 |
| `api.pushAway(target, self)` | 상대의 이동 방향을 바깥쪽으로 변경 |
| `api.projectile(self, angle, params)` | 탄환 생성. 각도는 라디안, params는 speed·damage·bounces |
| `api.dash(self, target, params)` | 돌진. params는 speed·damage·duration |
| `api.shield(self, params)` | 보호막. params는 amount·duration |
| `api.orbit(self, params)` | 회전 무기. params는 damage·count·range·duration·speed |

지속 효과는 아래의 능력 확장 규약을 사용하면 동작과 렌더링을 한 파일에서 작성할 수 있습니다. 기존 엔진에 없는 공통 시스템(예: 다수 소환수 간 충돌)이 필요한 경우에는 엔진도 확장할 수 있습니다.

## 파일 역할과 검증

- `index.html`: 경기 화면과 편집 화면
- `styles.css`: 화면 디자인과 모바일 레이아웃
- `characters.js`: 처음 접속했을 때의 기본 캐릭터와 능력
- `abilities.js`: 능력별 동작과 편집 항목
- `engine.js`: 충돌, 반사, 체력, 쿨타임, 승패와 설정 검증
- `app.js`: 화면 표시, 편집, 저장과 불러오기
- `sound.js`: 캐릭터의 벽 충돌음. 대전 시작을 누른 후 작동하며 음소거 가능
- `tests/engine.test.cjs`: Node.js에서 `node tests/engine.test.cjs`로 실행

검사는 같은 캐릭터 대전, 탄환 소유권, 돌진 피해, 회복·보호막·충격파·회전 무기, 새로운 동작 등록, 잘못된 설정 차단, 모든 기본 대진 160경기의 종료를 포함합니다. 유튜브 참고 영상에서 확인한 흰 경기장, 검은 테두리, 하단의 초록색 체력 바와 얇은 쿨타임 바를 반영했습니다. 영상 속 인물 사진과 고유 공격 이미지까지 복제한 것은 아니며, 캐릭터 사진은 편집 화면에서 추가할 수 있습니다. 완성된 화면의 브라우저 시각 검사와 실제 소리 청취는 실행 환경의 로컬 페이지 접근 제한으로 수행하지 못했습니다.

## 벽 충돌음

대전 시작 버튼을 누르면 소리가 활성화됩니다. 캐릭터가 벽에 반사될 때 짧은 합성 타격음이 납니다. 미사일 능력에는 별도의 발사음과 폭발음이 있습니다. 배경음악, 음성, 일반 탄환·캐릭터 접촉음은 없습니다. **소리 켜짐/꺼짐** 버튼으로 모든 소리를 함께 조절합니다. 원본 영상에서 추출한 음원은 아닙니다. 모서리에서의 중복 발음과 과도한 연속 소리를 제한했습니다.

추가 검사: `node tests/sound.test.cjs` (오디오 이벤트와 합성 호출 검증, 실제 청취 검사는 아님).

## 늘어나는 코와 타격 연출

캐릭터 선택 목록에서 **코 늘리기**를 고르고 **대전 시작**을 누르면 됩니다. 기존 저장 데이터가 있어도 새 코 능력과 예시 캐릭터가 보관함에 추가됩니다(보관함의 최대 개수 이내). 기존 캐릭터의 능력·사진은 덮어쓰지 않습니다. 편집 화면에서 다른 캐릭터에도 **쭉 늘어나는 코**를 장착할 수 있습니다.

발동 순간 상대 방향을 잡고 코가 늘어남 → 잠깐 유지 → 회수 순서로 움직입니다. 상대가 실제 코의 범위에 닿을 때 1회 피해가 들어갑니다. 빗나갈 수 있으며 벽을 넘지 않습니다. 피해, 길이, 두께, 늘어나는 시간·유지 시간·회수 시간을 편집할 수 있습니다. 코는 직접 그린 도형이며 원본 사진에서 추출한 코 이미지는 아닙니다.

적중하면 피해 숫자, 방사형 타격 표시, 잠깐의 화면 흔들림과 옅은 붉은 플래시가 나타납니다. 보호막으로 전부 막으면 ‘방어’로 표시하며 화면의 붉은 플래시는 생기지 않습니다. **타격 연출 켜짐/꺼짐**으로 조절합니다. 시스템의 동작 줄이기 설정이 켜져 있으면 기본적으로 연출을 끕니다. 코 능력은 별도 소리가 없으며 벽 충돌음과 미사일 효과음만 사용합니다.

## 다음에 요청할 능력을 추가하는 구조

사용자는 원하는 능력을 말로 요청하면 됩니다. 현재 여섯 가지 기본 종류에 한정되지 않습니다. 추가 능력은 `ability-packs.js`에서 등록합니다. 새 파일로 나눌 때는 `index.html`에서 `abilities.js` 뒤, `app.js` 앞에 그 파일의 script 태그를 추가합니다. JSON 불러오기는 수치 설정용이며 실행 코드를 불러오는 기능은 아닙니다.

각 능력은 `label`, `description`, `fields`, `cast`를 갖습니다. 지속 애니메이션이나 자체 판정이 필요하면 아래처럼 `update`와 `draw`도 같은 능력 안에 작성합니다.

```js
globalThis.ArenaAbilities.mySkill = {
  label: '새 능력',
  description: '내가 요청한 새로운 동작',
  fields: {},
  cast(api, self, target, params) {
    api.effect('mySkill', self, { age: 0, hit: false }, 1.2);
  },
  update(effect, api, self, target, dt) {
    effect.age += dt;
    // 이동·상태·타격 판정. 적중 시 api.damage(target, 피해량, self).
    // 한 번만 적중해야 하면 effect.hit 같은 상태로 중복을 막습니다.
  },
  draw(ctx, effect, self, target) {
    // Canvas 2D로 이 능력만의 모습을 그립니다.
    // 이 함수에서는 게임 상태를 바꾸지 않습니다.
  }
};
```

`api.effect(type, self, state, duration)`의 state에는 JSON으로 복사 가능한 값만 넣습니다. type·owner·remaining은 엔진 예약 필드입니다. `update`는 전투가 진행될 때만 고정 간격으로 호출되고, `draw`는 현재 상태를 표시합니다. 엔진은 수명 종료와 새 경기에서 효과를 정리하고, 렌더러는 그리기 상태를 격리하며 경기장 밖을 잘라냅니다. `api.damage`로 피해를 주면 공통 타격 연출이 자동으로 적용됩니다. 능력 실행 코드는 신뢰할 수 있는 프로젝트 파일로만 추가하세요.

검사: `node tests/abilities.test.cjs` — 양쪽 슬롯의 코 적중, 1회 피해, 빗나감, 회수·만료, 일시정지, 보호막, 타격 이벤트와 별도 지속 능력 등록. 브라우저 화면의 시각 검사는 로컬 페이지 접근 제한으로 수행하지 못했습니다.

기본 캐릭터와 새 캐릭터의 기본 체력·이동 속도는 각각 200입니다. 이전에 저장된 기본 캐릭터의 변경되지 않은 기본 수치도 한 번 갱신합니다. 직접 수정한 수치와 사용자 생성 캐릭터는 유지됩니다.

## 시작 카운트다운

대전 시작을 누르면 3 → 2 → 1 동안 캐릭터 옆 방향 화살표가 회전하다가 서서히 멈춥니다. 마지막 0.3초 동안 출발 방향을 고정해서 보여준 뒤 해당 방향으로 출발합니다. 준비 중에는 이동·공격·스킬 쿨타임·경기 시간이 진행되지 않습니다. 경기 속도를 바꿔도 카운트다운은 기본 3초입니다. 카운트다운 소리는 없습니다. 전투 중 벽 충돌음과 미사일 효과음만 사용됩니다. 일시정지와 화면 이탈 시 준비 동작도 정지하며, 다시 준비·캐릭터 변경 시 초기화됩니다.

`countdown.js`는 시작 연출을 관리합니다. 검사: `node tests/countdown.test.cjs`.

## 미사일 쏘기

캐릭터 · 능력 편집에서 원하는 캐릭터를 선택하고 **미사일 쏘기**를 체크한 다음 캐릭터를 저장하세요. 이 능력은 새 능력 보관함에 자동 추가되며, 캐릭터에는 직접 장착합니다. 별도의 바로 체험 버튼이나 자동 장착은 없습니다.

- 기본값: 2초마다 돈 1개, 돈 3개로 유도 미사일 1발, 피해 55, 속도 360, 최대 추적 8초.
- 돈은 경기장 안의 무작위 위치에 내려옵니다. 0.35초 낙하를 마친 뒤에 몸이 닿으면 수집합니다. 일반 캐릭터는 통과만 하고 수집할 수 없습니다.
- 필요한 돈을 모으면 자동으로 차감하고, 제자리에 멈춰 3·2·1 장전을 끝낸 뒤 상대를 추적하는 미사일을 발사합니다. 시간 경과나 일반 쿨타임만으로 발사하지 않습니다.
- 체력 아래 능력 표시가 **돈 0 / 3** 형태로 바뀝니다. 수집 시 바닥에 +1이 표시됩니다.
- 돈은 양쪽 보유자가 함께 주울 수 있는 공용 자원입니다. 두 명 모두 능력이 있어도 중복 생성하지 않습니다. 서로 다른 낙하 간격이면 더 짧은 간격을 사용합니다. 한 캐릭터에는 이 종류 능력을 하나만 장착할 수 있습니다.
- 돈은 24초 뒤 사라지고 바닥에 최대 4개까지 남습니다. 여러 개를 동시에 주워도 필요한 돈만 차감하고 남은 돈은 보관합니다. 매 발사마다 3초 장전이 필요하며 발사 직후 0.6초 동안 다시 장전을 시작하지 않습니다.
- 미사일은 제한된 회전 속도로 유도됩니다. 벽에 닿거나 추적 시간이 끝나면 사라지며, 상대에 적중할 때만 피해·폭발 이펙트·폭발음이 한 번 발생합니다.
- 발사 시 피슝 하는 합성음, 적중 시 저음과 잡음을 섞은 폭발음이 재생됩니다. 주황색 폭발·연기 조각·충격 고리·화면 흔들림을 표시합니다. **타격 연출 꺼짐**이면 추가 타격 연출을 끄되 돈과 미사일 자체는 계속 보입니다.
- 카운트다운·일시정지 동안에는 낙하·수집·유도·수명이 진행되지 않습니다. 새 경기는 돈과 미사일을 초기화합니다.

능력 보관함에서 수집 개수, 낙하 간격, 피해, 미사일 속도, 회전 속도, 추적 시간을 수정할 수 있습니다. 이 능력에서는 불필요한 쿨타임 입력란을 숨깁니다.

`missile-ability.js`가 수집·유도·그림을 담당합니다. 추가 능력의 `trigger: 'pickup'`은 경기 시작 시 한 번 초기화하고, 매 프레임 조건을 직접 판정하는 방식입니다. `status(self, skill)`은 자원 표시를 제공하며, `api.shared`는 경기별 공용 상태, `api.now`는 경기 시간, `api.random`은 경기 난수, `api.sound`는 소리 이벤트, `api.explosion`은 피해와 폭발 연출을 제공합니다. 저장된 JSON에는 실행 코드를 넣지 않습니다.

검사: `node tests/missile.test.cjs`, `node tests/sound.test.cjs`. 수집 자격, 필요한 돈 충족 및 차감, 자동 쿨타임 발사 방지, 공용 낙하, 유도 방향, 1회 피해·폭발, 양쪽 슬롯, 일시정지, 음소거와 합성 호출을 검증했습니다. 실제 브라우저 화면과 소리의 청취 검사는 수행하지 못했습니다.

### 미사일 연출 업데이트

바닥에 떨어지는 중인 돈까지 합쳐 최대 4개입니다. 수집으로 줄어들면 기존 낙하 간격에 맞춰 4개까지만 다시 채웁니다. 돈 그림은 기존의 1.5배, 미사일 그림은 1.8배로 키웠고 충돌 범위도 조정했습니다. 미사일 피해 기본값은 이후 강화에서 55로 올렸습니다.

돈을 모으면 차감 후 캐릭터가 제자리에서 3초간 멈추고 3·2·1 숫자와 장전 고리가 보입니다. 이 동안 돈을 추가로 줍거나 다른 일반 능력을 새로 발동하지 않지만, 상대의 공격은 받을 수 있습니다. 상대는 계속 움직입니다. 발사하면 이동을 재개합니다. 미사일 장전 시간은 경기 속도를 따르며, 일시정지하면 함께 멈춥니다.

숫자 전환에는 짧은 준비음, 발사 순간에는 저음 충격과 길어진 분사음을 넣었습니다. 발사 때도 짧게 화면이 흔들립니다. 기존 소리·타격 연출 토글을 그대로 사용합니다. 최대 4개와 보충, 장전 중 위치 고정, 3초 후 1회 발사, 장전 일시정지 및 음소거를 검사했습니다. 실제 소리 청취·화면 시각 검사는 수행하지 못했습니다.

## 충돌과 발사관 연출 개선

캐릭터가 겹치면 서로 반대 방향으로 충분히 떨어지도록 위치와 출발 속도를 함께 보정합니다. 서로 속도가 다르거나 같은 방향으로 움직이는 경우, 돌진 중인 경우에도 각자의 이동 속도를 유지하며 분리됩니다. 장전 중 멈춘 캐릭터는 고정 물체로 처리합니다. 벽 바로 앞에서는 벽을 향해 되튕기며 다시 겹치는 대신 벽을 따라 빠져나갈 방향을 선택합니다. 고정 캐릭터와 벽 사이에 끼면 가까운 빈 방향으로 위치를 보정합니다.

미사일 준비 시 캐릭터가 주머니에서 빨간 버튼 리모컨을 꺼냅니다. 별도 패널에 03·02·01이 표시되고 마지막 순간 손가락으로 버튼을 누릅니다. 빨간 버튼이 눌리고 안테나에서 신호 표시가 나온 뒤 리모컨을 다시 넣습니다. 캐릭터에 대포나 발사관은 표시하지 않습니다.

`node tests/collision.test.cjs`: 정면 충돌, 같은 방향, 서로 다른 속도, 돌진, 고정 장전, 벽, 모서리, 벽 사이 끼임, 중심이 겹친 경우의 분리와 경계를 검사합니다. 실제 브라우저 시각 검사는 수행하지 못했습니다.

돈은 서로 150 이상 떨어져 생성되고, 주운 자리의 반경 180에는 8초 동안 다시 생성되지 않습니다(720 크기 경기장 좌표 기준). 캐릭터 바로 앞도 피합니다. 조건에 맞는 빈 자리가 없으면 해당 낙하를 건너뛰며, 거리 제한을 무시해서 생성하지 않습니다.

## 리모컨 스위치와 외부 미사일

사용자가 제공한 그림처럼 회색 직육면체 몸체, 검은 안테나와 끝의 둥근 부분, 전면의 빨간 원형 버튼을 Canvas로 그렸습니다. 실제 이미지 파일을 외부로 전송하거나 저장 데이터에 넣지 않습니다. 돈을 모으면 자동으로 리모컨을 꺼내고, 3·2·1이 끝나는 순간 손가락이 버튼을 눌러 발사 신호를 보냅니다. 사람이 직접 클릭할 필요는 없습니다.

캐릭터 앞의 대포는 제거했습니다. 미사일은 경기장의 위·아래·왼쪽·오른쪽 중 한 곳 바깥에서 생성되어 상대를 향해 진입한 뒤 계속 추적합니다. 진입 전에는 테두리에 접근 방향 표시가 보이며, 최초 진입 전 바깥에 있다는 이유로 소멸하지 않습니다. 진입 후 다시 경계 밖으로 나가거나 수명이 끝나면 사라집니다.

버튼 클릭음, 발사음, 비행 중 지속되는 추진음, 명중 시 폭발음을 구분했습니다. 비행음은 미사일 개수와 무관하게 한 겹만 재생해서 중첩되지 않습니다. 미사일이 모두 사라지거나 경기 종료·일시정지·음소거·새 경기 준비 시 즉시 정리합니다. 다시 진행할 때 미사일이 남아 있으면 비행음도 재개합니다. 초기 돈 개수·수집 규칙·피해 55·3초 준비는 유지합니다.

검증: 외부 생성과 정상 진입, 유도·단일 적중, 리모컨 꺼내기/누르기/회수 단계의 그리기 호출, 비행음의 중복 방지·중단·재개와 기존 편집 기능을 검사했습니다. 실제 브라우저 화면 및 소리 청취 검사는 수행하지 못했습니다.

## 충돌 시 살짝 회전, 코 사진 적용

캐릭터끼리 부딪힐 때 서로 스치는 방향에 따라 살짝 추가 회전이 걸렸다가 시간이 지나면 원래 속도로 가라앉습니다. 완전히 정면으로만 부딪히면 추가 회전이 거의 붙지 않고, 비스듬히 스칠수록 더 도는 식입니다. 여기에 더해 캐릭터는 부딪히지 않아도 항상 아주 천천히 계속 회전합니다. 회전은 캐릭터 사진(또는 기본 눈 두 개)에 함께 적용되며, 상대를 향하는 기본 방향 위에 더해지는 값이라 원래의 "상대 바라보기" 동작은 그대로 유지됩니다. 장전 중 고정된 캐릭터는 이 상시 회전도, 충돌로 인한 추가 회전도 멈춥니다.

**늘어나는 코**의 모습을 사용자가 준 사진(피부색 계열의 길쭉한 형태)으로 교체했습니다. 사진의 넓은 쪽 끝이 상대를 향해 뻗어나가고, 뾰족한 끝이 캐릭터 몸통에 붙습니다. 사진은 `assets/nose.png`로 보관하고 `media.js`에 base64로 함께 담아 `file://`로 열어도 바로 보이도록 했습니다. 사진 로딩 전 짧은 순간에는 기존 그라디언트 도형으로 대체 표시됩니다.

이후 사용자가 정면에서 본 코 모양의 새 사진을 보내와 다시 교체했습니다. 원본은 워터마크가 찍힌 미리보기용 스톡 이미지였어서, 그대로 쓰지 않고 다음처럼 다듬었습니다: 촘촘한 중간값 필터로 콧볼 위에 얹힌 워터마크 글자·로고를 흐려서 지우고, 원본에 이미 있던 투명 배경 알파 채널의 경계를 깨끗하게 다듬고(옅게 남은 워터마크 잔상 포함), 콧구멍이 있는 넓은 쪽 끝이 상대를 향하도록 위아래를 뒤집었습니다.

사진이 캐릭터에 붙는 쪽 끝은 원래 사진 자체가 뾰족해서, 그대로 늘리면 몸통과 코 사이가 가늘어져 떨어져 보이는 문제가 있었습니다. 처음에는 이음매에 살색 타원을 따로 덧그려서 메웠는데, 이러면 사진 코와 그 타원이 서로 다른 덩어리 두 개가 이어 붙은 것처럼 보였습니다. 그래서 덧그리는 도형을 없애고, 사진 한 장을 원래 두께의 1.6배로 조금 더 통통하게 늘려 그리는 방식으로 바꿨습니다 — 판정 두께(피해 범위)는 그대로 두고 화면에 보이는 굵기만 넓혀서, 하나로 이어진 사진 한 장이 쭉 늘어나는 모습을 유지합니다.

검증: `node tests/collision.test.cjs`에 충돌 시 스핀 발생과 시간에 따른 감쇠, 충돌이 없어도 계속되는 상시 회전, 장전 중 고정 캐릭터는 회전하지 않는 것까지 검사를 추가했습니다. 실제 브라우저 화면의 시각 검사는 로컬에서 대전을 실행해 코 사진 적용과 회전을 눈으로 확인했습니다.

## 미사일 사진 교체, 폭발 흔들림 강화

**미사일 쏘기**의 미사일 모습을 사용자가 준 로켓 사진으로 교체했습니다. 사진의 뾰족한 코 부분이 항상 이동 방향을 향하도록 그리며, 기존보다 조금 더 크게(가로 150px 기준) 표시합니다. 기존 정사각형 아이콘용 45도 보정 회전은 제거하고, 사진의 실제 가로세로 비율 그대로 그립니다. 사진은 `assets/missile.png`로 보관하고 `media.js`에 base64로 함께 담았습니다. 코 사진과 미사일 사진 모두 배경을 투명하게 오려냈습니다(배경과 이어진 영역만 지우는 방식이라 미사일 몸체의 밝은 색 줄무늬 같은 내부 디테일은 남습니다).

미사일이 상대에게 명중해 폭발할 때 경기장이 흔들리는 세기를 크게 올렸습니다(기존 대비 약 4배). 다른 타격의 흔들림, 화면 붉은 틴트, 폭발 자체의 고리·연기·화면 흔들림 연출은 그대로입니다.

검증: 기존 `node tests/missile.test.cjs`가 폭발 시 `kind: 'explosion'` 이벤트 발생을 그대로 검사합니다. 미사일 사진과 코 사진은 실제 임베드 데이터를 불러와 여러 각도로 그려보는 방식으로 방향·비율·투명 배경을 확인했습니다. 흔들림 세기 자체(수치 로직)는 코드로 확인했고, 실제 화면에서 흔들리는 모습의 청취·시각 검사는 수행하지 못했습니다.

## 충돌음·코 타격음 추가, 피격 플래시 강화

캐릭터끼리 부딪힐 때 사용자가 준 주먹 효과음(`assets/punch.wav`)이 재생됩니다. 접촉 피해와 같은 조건(0.35초에 한 번)으로 울려서, 서로 스치듯 계속 닿아 있어도 소리가 연타되지 않습니다. **늘어나는 코**가 실제로 적중하는 순간에는 사용자가 준 칼 소리(`assets/sword.mp3`)가 한 번 재생됩니다. 두 소리 모두 `media.js`에 base64로 함께 담았고, 기존 미사일 발사음·폭발음과 같은 방식(임베드 샘플 재생)으로 다룹니다. `sound.js`가 다루는 샘플을 미사일 전용 하나에서 미사일·충돌·코 세 가지로 넓혔습니다.

원래도 피해를 입으면 캐릭터가 짧게 빨갛게 번쩍이는 연출이 있었는데(`target.flash`), 지속 시간이 0.16초로 짧고 사진 캐릭터의 경우 최대 45% 투명도라 눈에 잘 안 띄었습니다. 지속 시간을 0.22초로, 사진 캐릭터의 최대 투명도를 60%로 올려 더 잘 보이게 했습니다. 기본 도형 캐릭터(사진 없는 경우)는 원래부터 몸 전체 색이 바뀌는 방식이라 그대로 두었습니다.

검증: `node tests/collision.test.cjs`에 충돌 시 부딪히는 소리 이벤트가 정확히 한 번 발생하고 접촉 쿨타임 동안 반복되지 않는 검사를, `node tests/abilities.test.cjs`에 코 적중 시 타격음 이벤트가 정확히 한 번 발생하는 검사를, `node tests/sound.test.cjs`에 두 샘플의 로드·재생·음소거 검사를 추가했습니다. 실제 오디오 컨텍스트로 두 소리가 정상 재생되는 것도 확인했습니다. 실제 청취 검사, 피격 플래시의 실제 화면 시각 검사는 수행하지 못했습니다.

## 리모컨 모양 교체, 먼저 누르고 기다리는 순서로 변경

**미사일 쏘기**의 리모컨을 사용자가 준 새 사진(지그재그 안테나, 기울어진 몸통)에 맞춰 다시 그렸습니다. 안테나를 매끈한 직선 대신 꺾인 선으로 바꾸고, 리모컨 몸통 전체를 살짝 기울여 그립니다. 이 리모컨은 사진을 그대로 붙여넣지 않고 이전처럼 Canvas 도형으로 그립니다(모양만 새 사진을 참고).

동작 순서도 바꿨습니다. 원래는 리모컨을 꺼내고 3초를 기다린 뒤 마지막 순간에 버튼을 눌러 발사했는데, 이제는 리모컨을 꺼내자마자(약 1초 안에 다 나오고, 누르고, 손을 뗌) 버튼을 한 번 눌렀다 손가락을 떼고, 그 뒤로 3초 카운트다운(3·2·1)이 진행되다가 끝나면 미사일이 날아옵니다. 손가락은 누른 직후 바로 떼며 카운트다운 동안 버튼을 붙잡고 있지 않습니다. 카운트다운 중에는 리모컨이나 손 연출 없이 숫자만 표시됩니다(캐릭터 머리 위 작은 원 안에 3·2·1). 돈을 모아서 리모컨을 꺼내는 시점부터 발사까지 걸리는 총 시간은 3초에서 4초로 늘었습니다(꺼내고 누르고 손 떼는 데 1초, 카운트다운 3초).

버튼을 처음 누르는 순간 리모컨 클릭음이 한 번 재생됩니다. 카운트다운 숫자가 바뀔 때(3이 뜰 때, 2로 바뀔 때, 1로 바뀔 때) 사용자가 준 폭탄 타이머 효과음(`assets/tick.wav`)에서 짧게 오려낸 똑딱 소리가 정확히 3번만 울립니다. 원래 있던 합성음 장전 틱은 이 소리로 완전히 대체했습니다.

검증: `node tests/missile.test.cjs`의 발사 시퀀스 검사를 새 타이밍(1초+3초)에 맞춰 다시 계산했고, 누르는 순간 클릭음이 정확히 한 번, 카운트다운 틱이 정확히 3번(3·2·1) 나는 것을 확인합니다. `node tests/sound.test.cjs`에 틱 샘플의 로드·재생·음소거 검사를 추가했습니다. 리모컨의 새 모양과 "누르고 손 떼기 → 숫자만 카운트다운" 순서는 실제 타이밍 값(충전 시간 3.9~0)으로 그려본 일곱 장면을 나란히 렌더링해서 눈으로 확인했습니다.

## 새 능력: 방구 흔적

리그 오브 레전드의 신지드 독 장판을 참고한 능력입니다. 쿨타임(기본 5초)마다 발동해, 그 뒤 3초(흔적 남기는 시간, 조절 가능) 동안 0.2초 간격으로 그 순간 서 있는 자리에 방구 구름을 계속 남깁니다. 캐릭터가 그동안 움직이면 지나온 길을 따라 구름이 촘촘하게 이어져 실제 이동 경로가 그대로 드러납니다. 각 구름은 놓인 자리에 고정되며(캐릭터를 따라다니지 않음) 자기 지속 시간(기본 4초, 조절 가능)이 끝나면 개별적으로 사라집니다 — 3초 동안 만들어진 구름들이 각자 따로 페이드아웃되는 방식이라, 흔적 남기는 시간이 끝난 뒤에도 마지막 구름들은 한동안 더 남아있습니다. 구름 범위 안에 있으면 상대만 0.4초마다 조금씩 피해를 입습니다 — 자기 자신은 자신의 흔적에 피해를 입지 않습니다. 피해·범위·흔적 남기는 시간·구름 지속 시간을 편집할 수 있습니다.

모습은 냄새 연출(방귀 뿡뿡 모양, 줄무늬) 없이 사용자가 준 참고 그림처럼 반투명한 원이 겹쳐진 아주 단순한 형태로 그립니다. 여러 개가 겹치는 자리는 캔버스의 반투명 겹침 효과로 자연스럽게 더 진하게 보입니다.

다른 커스텀 능력(코, 미사일)과 같은 방식으로 `ability-packs.js`에 등록했고, `app.js`에 미사일처럼 능력 보관함에만 자동으로 추가됩니다(전용 데모 캐릭터는 만들지 않았습니다 — 원하는 캐릭터에 직접 장착해서 사용하세요).

검증: `node tests/fart.test.cjs` — 이동한 경로를 따라 구름이 계속 생기는지, 흔적 남기는 시간이 끝나면 더 이상 새 구름이 생기지 않는지, 자기 자신은 무피해인지, 범위 안의 상대에게는 피해가 들어가는지, 범위 밖은 무피해인지, 구름이 놓인 자리에 고정되어 나중에 밟아도 피해를 입는지, 가장 먼저 생긴 구름이 자기 지속 시간이 끝나면 (아직 안 끝난 다른 구름들과 별개로) 사라지는지, 모든 구름이 사라지면 흔적 효과 자체도 정리되는지, 여러 번 발동하면 흔적이 여러 겹 남는지, 체력이 0 밑으로 내려가지 않는지, 그리기 함수가 예외 없이 동작하는지를 검사합니다. 직선으로 이동하는 시뮬레이션을 캔버스에 그려서 사용자가 준 참고 그림처럼 반투명한 원이 겹쳐진 모양으로 나오는 것을 확인했고, 실제 게임 편집 화면에도 능력이 정상적으로 나타나는 것을 확인했습니다. 실제 화면에서의 시각 검사는 수행하지 못했습니다.
